# The DM app moves under /dm; / becomes a landing page

The cloud deployment wants a public landing page at the root of its domain, with the app below it. To keep the shared client identical everywhere, both shells use the same paths.

## Paths

| Page | Before | After |
|---|---|---|
| Landing | — | `/` |
| DM home | `/` | `/dm` |
| Login | `/login` | `/dm/login` |
| DM game | `/games/:id` | `/dm/games/:id` |
| Scene editor | `/scenes/:id` | `/dm/scenes/:id` |
| Assets / Data | `/assets`, `/data` | `/dm/assets`, `/dm/data` |
| Player page | `/g/:token` | unchanged |

- **Old paths redirect** with a 301, keeping the query string (for example `?next=`), so bookmarks and open tabs keep working.
- `/css`, `/js`, `/favicon.svg`, `/static` and `/api` are unchanged.
- **The self-hosted landing page** (`client/landing.html`) is a simple welcome card with an "Enter the DM page" button. The cloud serves its own landing page at `/` instead.

## Changes
- **Client:**
  - The "← Home" links point at `/dm`.
  - Links, redirects and `?next=` targets carry the `/dm` prefix (`common.js`, `login.js`, `home.js`, `dm.js`, `data.js`, `assets.js`, and the page headers).
  - New `client/landing.html`.
- **`server/index.js`:** serves `/` (landing) and the `/dm/…` pages, and redirects the old paths.
- **`test/pages.test.js`:** checks the landing page, every `/dm` page, and the redirects.

## Core/shell impact
- Core: none.
- Shell: the self-hosted page routes (`server/index.js`). The cloud shell's CloudFront page-rewrite function maps the same paths.
- Contract change: yes. Part 3 of `docs/2026_10_16_001_CORE_SHELL_SPLIT.md` now lists the page paths a shell must serve.
